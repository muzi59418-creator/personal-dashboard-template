# 版本规则

## 当前规则

- 当前已完成的旧版能力统一作为 v1.0.0 基线。
- v1.1.0：今日工作台、计划执行日、工作模板。
- v1.2.0：例行工作规则升级。
- v1.3.0：项目推进清单、项目转工作、自动进度。
- v1.3.4：项目详情右侧抽屉、项目卡片下一步预览、项目详情快捷编辑。
- v1.3.5：修正历史更新日志重复版本号。
- v1.3.6：今日工作台视觉紧凑优化。
- v1.3.7：灵感命名与项目推进体验优化。
- v1.3.8：更新日志展示优化。
- v1.3.9：首页、项目详情和设置页视觉密度优化，并补齐历史更新日志版本号。
- v1.4.0：项目详情抽屉与时钟视觉优化。
- v1.4.1：仪表板视觉设计美化，统一卡片、按钮、表单、弹窗和响应式体验。
- v1.4.2：首页轻科技视觉升级，强化统计卡、快速记录、完成概览和首页模块层次。
- v1.4.3：首页信息密度优化，精简今日例行与空状态，并压缩快速记录和完成概览高度。
- v1.4.4：首页工作台体验优化，居中完成率数字，统一今日例行空状态，让项目推进展示全部未完成事项及所属项目名称。
- v1.4.4 补充优化：重构 GitHub 项目介绍并更新真实页面截图；不升级版本号，不改变业务逻辑、数据结构或存储边界。
- v1.5.0：侧栏展示当前登录账号，统一今日工作台轻量空状态，首页工作日记限制为最近 3 个自然日。
- v1.6.0：项目管理页升级为四象限折叠项目树，支持最多 5 层、推进事项、递归进度、自动状态、移动和详情抽屉；schema 升级为 1.4.0。
- v1.6.1：优化项目树拖拽命中与视觉反馈、末尾追加、项目弹窗、统计卡和删除确认；移除项目管理页 3 个筛选项；编号改为基于树结构和 `sortOrder` 的派生展示，不新增数据迁移。
- v1.6.2：首页任务文案、项目树辅助信息、首页项目看板布局和更新日志展示优化；浏览器标签统一为“个人工作台”。
- 每个正式发布版本，本地正式版、GitHub 开源模板、本地 Skill 包必须使用同一版本号。
- 版本字段统一使用 `1.0.0`、`1.1.0` 这种无 `v` 前缀格式。
- 页面标题、README、更新日志、Git Tag 显示时可使用 `v1.6.1`。
- 不篡改旧 Git 历史、旧 Tag 或已发布版本记录。
- 仅在无冲突时新增 `v1.0.0` 基线 Tag。

## 部署基础设施版本边界

- GitHub Pages 工作流、Vite base 适配和公开部署文档属于开源基础设施变更，不修改 `APP_VERSION`、`SCHEMA_VERSION`、数据结构、localStorage key、Supabase 表结构或云同步载荷。
- 本次公开体验部署不纳入 v1.6.2 或其他正式版本的功能清单，保持在 `Unreleased` 记录中，待用户确认后再决定后续发布安排。
- 本次不创建 Git Tag、GitHub Release，也不改变既有版本的提交历史。

## 数据兼容

- 浏览器本地数据继续使用 `personal-dashboard-template:v1` 存储键。
- 旧 JSON 备份缺少 `appVersion`、`schemaVersion`、`plannedDate`、`workTemplates` 时，导入后自动补默认值。
- v1.2.0 读取旧 localStorage 时会先保存 `personal-dashboard-template:v1:backup-before-v1.2.0`，再补例行规则和单次例行工作追溯字段。
- v1.3.0 读取旧 localStorage 时会先保存 `personal-dashboard-template:v1:backup-before-v1.3.0`，再补项目来源字段和迁移标记。
- v1.4.1 不新增数据结构迁移，继续沿用 v1.3.0 的 `schemaVersion` 和 `personal-dashboard-template:v1` 存储键。
- v1.4.2 仅升级视觉与版本面，继续沿用 v1.3.0 的 `schemaVersion` 和 `personal-dashboard-template:v1` 存储键。
- v1.4.3 仅调整首页展示密度，继续沿用 v1.3.0 的 `schemaVersion` 和 `personal-dashboard-template:v1` 存储键。
- v1.4.4 仅调整首页展示与项目推进筛选，不改变完成率统计口径、项目进度算法或数据结构，继续沿用 v1.3.0 的 `schemaVersion` 和 `personal-dashboard-template:v1` 存储键。
- v1.5.0 仅复用登录会话展示账号名称并调整首页查询与空状态，不修改账号、本地日记或其他持久化结构，继续沿用 v1.3.0 的 `schemaVersion` 和 `personal-dashboard-template:v1` 存储键。
- v1.6.0 在保持 `personal-dashboard-template:v1` 存储键不变的前提下，将旧项目迁移为统一项目节点字段：`parentId`、`rootProjectId`、`depth`、`isDelayed`、`note`；旧字段继续保留，迁移前备份为 `personal-dashboard-template:v1:backup-before-v1.6.0`，schemaVersion 为 `1.4.0`。
- v1.6.1 不修改项目数据结构、`parentId`、`sortOrder`、localStorage key、Supabase 表结构或云同步载荷；项目编号仅在界面按当前树结构和兄弟顺序派生。旧项目名称中的手写编号保留，不做批量清洗，不执行一次性迁移，也不覆盖现有备份。
- 新导出 JSON 包含 `version`、`appVersion`、`schemaVersion`。
- v1.6.2 仅调整界面文案、更新日志内容和首页布局，不修改项目数据结构、统计逻辑、localStorage key、Supabase 表结构或云同步载荷，继续沿用 schemaVersion `1.4.0`。
- 不删除旧字段；新增字段通过归一化迁移补齐。
- 旧项目 `progress` 手动进度字段继续保留，但页面项目进度按推进事项自动计算。
- 开源模板只保留通用演示数据，不包含私人工作数据、私有路径或账号信息。

## v1.6.0 项目模块发布边界

- 项目树最多 5 层；子项目不单独拥有四象限，统一继承 L1 主项目象限。
- 有直属子项目时，项目进度为直属子项目进度平均值；无子项目但有推进事项时，按完成率计算；两者都没有时显示 `—`。
- 基础状态由进度自动推导，延期单独人工维护；删除主项目会明确提示并级联删除下级项目与推进事项。
- 同一 L1 主项目内支持节点移动与推进事项移动，禁止跨主项目、自身后代和超过 5 层的目标。

## v1.3.0 项目模块发布边界

- 保留 v1.1.0 今日工作台、计划执行日、工作模板、工作职责和 JSON 导入导出能力。
- 保留 v1.2.0 例行工作、节假日、顺延、暂停和恢复逻辑。
- 仅升级项目推进清单、项目转工作和项目进度自动计算，不新增里程碑、甘特图、日历、多人协作或提醒系统。
- 项目状态继续由用户手动维护，推进事项全部完成时不自动把项目状态改成已完成。
- 中国法定工作日历放在独立配置文件中，新增年份只维护配置，不修改业务逻辑。
