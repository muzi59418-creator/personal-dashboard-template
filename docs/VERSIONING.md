# 版本规则

## 当前规则

- 当前已完成的旧版能力统一作为 v1.0.0 基线。
- v1.1.0：今日工作台、计划执行日、工作模板。
- v1.2.0：例行工作规则升级。
- v1.3.0：项目推进清单、项目转工作、自动进度。
- v1.3.4：项目详情右侧抽屉、项目卡片下一步预览、项目详情快捷编辑。
- v1.3.5：修正历史更新日志重复版本号。
- v1.3.6：今日工作台视觉紧凑优化。
- v1.3.7：灵感命名与项目推进体验优化。
- v1.3.8：更新日志展示优化。
- 每个正式发布版本，本地正式版、GitHub 开源模板、本地 Skill 包必须使用同一版本号。
- 版本字段统一使用 `1.0.0`、`1.1.0` 这种无 `v` 前缀格式。
- 页面标题、README、更新日志、Git Tag 显示时可使用 `v1.3.8`。
- 不篡改旧 Git 历史、旧 Tag 或已发布版本记录。
- 仅在无冲突时新增 `v1.0.0` 基线 Tag。

## 数据兼容

- 浏览器本地数据继续使用 `personal-dashboard-template:v1` 存储键。
- 旧 JSON 备份缺少 `appVersion`、`schemaVersion`、`plannedDate`、`workTemplates` 时，导入后自动补默认值。
- v1.2.0 读取旧 localStorage 时会先保存 `personal-dashboard-template:v1:backup-before-v1.2.0`，再补例行规则和单次例行工作追溯字段。
- v1.3.0 读取旧 localStorage 时会先保存 `personal-dashboard-template:v1:backup-before-v1.3.0`，再补项目来源字段和迁移标记。
- v1.3.8 不新增数据结构迁移，继续沿用 v1.3.0 的 `schemaVersion` 和本地存储键。
- 新导出 JSON 包含 `version`、`appVersion`、`schemaVersion`。
- 不删除旧字段；新增字段通过归一化迁移补齐。
- 旧项目 `progress` 手动进度字段继续保留，但页面项目进度按推进事项自动计算。
- 开源模板只保留通用演示数据，不包含私人工作数据、私有路径或账号信息。

## v1.3.0 项目模块发布边界

- 保留 v1.1.0 今日工作台、计划执行日、工作模板、工作职责和 JSON 导入导出能力。
- 保留 v1.2.0 例行工作、节假日、顺延、暂停和恢复逻辑。
- 仅升级项目推进清单、项目转工作和项目进度自动计算，不新增里程碑、甘特图、日历、多人协作或提醒系统。
- 项目状态继续由用户手动维护，推进事项全部完成时不自动把项目状态改成已完成。
- 中国法定工作日历放在独立配置文件中，新增年份只维护配置，不修改业务逻辑。
